# RGB-D recording and moving-camera contracts

Status note (the text below is the original contract and is still what the reader enforces): since then two adapters write this recording format from real files (`d435_recording_adapter.py` for native `.db3`/`.bag`, `image_sequence_adapter.py` for the image-sequence export), WiLoR and three object providers produce observations from it (`run_perception.py`), and `RGBDFrame.point_from_xyz` admits a metric point computed from the frame's own registered depth with the same stamp rules as `point_at`. A second file contract exists beside this one: `sg-object-masks/1` (`objects.json` with the schema, the label map, the participant and session, `first_source_index` and `frames_written`; `masks/<index>.png`; `segmentation_provenance.json`), written by `segment_objects.py` and checked by `sg_offline.objects.MaskObjects` and `run_perception.build_object_provider`. The frame index in mask names, in `detections.jsonl` and in `frame_times.csv` is the position in this manifest, not the export's own frame number (the adapter sidecar keeps that as `source_frame_index_by_frame_id`). The optional per-frame `invalid_depth_value` is honoured by the hand points and by all three object providers.

Status: implemented and locally tested using synthetic inputs only. D435 is the planned device, not the source of the demonstration. No native capture, depth registration, image rectification, detector or camera-pose estimator is implemented here.

## Recording

`sg_offline.recordings.RGBDRecording` reads a JSON manifest using schema `sg-rgbd-recording/1`. Required top-level fields are `schema`, `participant_id`, `session_id`, `camera_model`, `calibration`, `frames`; extra fields are rejected. Use pseudonymous participant/session identifiers. Synthetic records must say they are synthetic, not name a physical device as measured.

Calibration fields: `calibration_id`, positive integer `width` and `height`, pixel intrinsics `fx`, `fy`, `cx`, `cy`, positive `depth_scale_m`, and `optical_frame`. Only `projection=rectified_pinhole` and `depth_convention=optical_z` are supported. The upstream adapter must establish registration and rectification rather than merely relabel raw images. Optical coordinates are x right, y down, z forward; depth becomes metres using the declared scale, not a hard-coded device assumption.

Each frame contains `frame_id`, `rgb_path`, `depth_path`, `rgb_stamp`, `depth_stamp`, `registered_to_rgb=true`, `max_sync_skew_s`, and optional `invalid_depth_value` (default zero). Arrays are local relative `.npy` paths within the recording directory; pickle loading is disabled. RGB is uint8 H×W×3; depth is numeric H×W at the calibrated resolution. Loaded arrays are copied read-only.

Stamps carry `sample_id`, `acquired_s`, `available_s`, `source`, `clock`. RGB and depth acquisition times must satisfy the explicitly chosen synchronization tolerance and use a mapped common clock. The tolerance is configuration, not an empirically established acceptable bound. Each stream requires strictly increasing acquisition times and unreused sample IDs; frame availability is nondecreasing. Availability cannot precede acquisition. The example manifest written by `run_rgbd_checks.py` (`recording.json` in its output directory) shows the exact serialized contract.

## Geometry and causal access

`RGBDFrame.point_at` takes an integer `(column,row)` or missing pixel, identity, functional-point definition, pixel-observation stamp and decision time. Pixels must refer to the frame's RGB acquisition; the image, depth and pixel observation must be available by decision time. Projection returns optical xyz metres with depth acquisition time and combined availability/source provenance. Missing pixels, out-of-view locations and invalid depth return explicit unavailable points, not zero positions. No uncertainty calibration is claimed.

For nonzero RGB/depth skew, the pixel and depth are not truly simultaneous; the adapter's synchronization budget must be validated against motion. The current implementation does not compensate scene motion between exposures or infer a noise model.

`CameraPose` takes a proper orthonormal rotation, translation in metres, source optical frame, distinct fixed target frame, pose identity and stamp. `transform` requires exactly matching point/pose acquisition time and clock, matching source frame and causal availability. Stale/future poses fail explicitly; interpolation and estimation are not implemented. Unmodeled pose uncertainty remains unknown, not spuriously precise. A supplied fixed-frame assertion is an upstream responsibility, not verified physical stationarity.

`same_time_distance` requires identical acquisition times, frames and clocks. Rigid transforms preserve this distance. Directional velocity additionally requires explicitly fixed points, unchanged calibration and compatible history; otherwise it is withheld. Relative scalar geometry does not substitute for every action's world-direction features. `RelativeGeometry` implements that scalar geometry: the same-time hand–object distance and its past-secant rate are computed per pair without any fixed frame, because that scalar is invariant to rigid camera motion. The rate feeds the approach-rate feature when directional velocities are withheld, is logged per row under `relative_geometry` with its own reason and source, and is refused for asynchronous points, frame/clock mismatch, calibration or definition changes and gaps. Directional velocity, normals and world-frame features still require a declared fixed reference.

## Migration and experiment boundary

Observation schema is now `sg-offline/3`: points default to a moving/unverified optical frame and include `frame_is_fixed`, `calibration_id`, `transform_id`. Versions 1 and 2 are rejected. Any migration must derive the frame declaration from actual provenance; do not set it true just to restore outputs.

The synthetic runner supplies known pixels and camera poses and tests three frames through two-hand simulation-only inference. It is neither an automatic perception demo nor a reference-validated estimator. Only grasp/no-request is demonstrated; five action providers remain missing. The next adapter requires a permitted D435 RGB-D sample with actual calibration and timestamps. Kinetics stays disabled pending a separate signal/target/reference admission experiment.
